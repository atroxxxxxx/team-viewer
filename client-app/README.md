# Клиентское приложение

Настольное приложение на Python и PyQt5. Стоит на машине клиента. Через него клиент описывает проблему, отдаёт экран и по желанию камеру, отвечает на запрос управления, выполняет шаги плана и подтверждает, что проблема ушла.

Приложение не слушает входящие соединения. И к сервису заявок, и к ретранслятору оно подключается само.

## Обязанности

- Форма заявки: текст проблемы и переключатель камеры. Экран в заявке выключить нельзя.
- После утверждения оператором — подключение к сессионному порту ретранслятора строкой `CLIENT`, uuid и секретом клиента из `GET /session`. ffmpeg публикует RTSP на localhost, мост отдаёт байты в ретранслятор. Камера — второй поток того же туннеля. Без секрета публикация не стартует.
- Чат, план и разрешение. Прототип опрашивает `GET /api/v1/tickets/{id}/session` раз в секунду.
- Диалог разрешения на мышь и клавиатуру. Отказ переводит сессию в план шагов, согласие включает приём команд ввода.
- Валидатор команд. Команда исполняется только после проверки на клиенте, даже если сервис заявок её уже пропустил. Правила — в [safety-policy](../safety-policy/README.md).
- Список TODO: показать шаги, отправить наблюдение по шагу, отобразить отметку оператора и вложенный план, если шаг породил новую проблему.
- «Решено» сразу закрывает заявку и отключает клиента, даже если шаги ещё открыты. «Не решено» требует текст и закрывает заявку как `closed`. Пока оператор переключается, клиент видит «Переключение на другого оператора».
- Остановка публикации, когда заявка перешла в `resolved` или клиент закрыл окно.

## Чего приложение не делает

- Не открывает порт для входящего RTSP и не показывает клиенту адрес, по которому поток можно было бы читать снаружи.
- Не исполняет произвольную оболочку. Разрешённый ввод — события мыши и клавиатуры в scope, который клиент подтвердил.
- Не исполняет текст с управляющими символами и не принимает код клавиши вне латиницы, цифр и `_`. Координаты указателя ограничены.

Сборка пакета для Debian описана в [DEBIANIZE.md](../DEBIANIZE.md).

## Запуск

Адреса и учётка лежат в `config.yaml`. `ticket` — схема, адрес и порт сервиса заявок. `relay` — хост и сессионный порт ретранслятора, не RTSP. `auth` — логин `client` и пароль. Пока nginx отдаёт локальный HTTPS, заявки идут на `https://127.0.0.1:443` с `tls_verify: false`. Если сертификата нет, ставятся `scheme: http` и `port: 8080`. Нужны сами сервисы и `ffmpeg`.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m client_app.main
```

Кнопка «Создать заявку» только регистрирует проблему. Экран уходит после того, как в сессии появляется `tunnel_id`. При ошибке захвата тестовый кадр не отправляется. Камера использует `/dev/video0`. После статуса `resolved` публикация останавливается.

Ввод с оператора исполняется через `xdotool` только после диалога разрешения и повторной проверки правил. Галка «опасный диалог» ставит событие на паузу и спрашивает ещё раз.

Безопасность обоих окон записана в [SECURITY.md](SECURITY.md). Риски и планы — в [RISKS.md](RISKS.md) и [PLANS.md](PLANS.md).

Настройки из окна сохраняются сразу после применения и восстанавливаются при запуске. Базовые адреса и учётные данные читаются из `config.yaml`; пользовательские настройки их дополняют. Файл пользовательских настроек не содержит паролей и токенов. Расположение и проверки описаны в [support-protocol](../support-protocol/README.md). Захват и управление на стороне клиента рассчитаны на Linux с X11 и `xdotool`; Windows и Wayland пока не поддерживаются. Отдельного пароля подключения и отмены заявки в протоколе нет.


Экран публикуется с частотой 60 FPS по умолчанию. В настройках можно задать любую положительную целую частоту без программного верхнего ограничения. Старые сохранённые профили с меньшей частотой обновляются до 60 FPS при запуске клиента; явный выбор другой частоты после обновления сохраняется. В окне оператора рядом с экраном показана измеренная частота отрисовки. После обновления кода перезапустите оба приложения.
