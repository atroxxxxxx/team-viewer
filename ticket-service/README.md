# Сервис заявок

Раздел отчёта про контракт и время отклика — в корневом [README.md](../README.md#api).

HTTP-сервис на Python (FastAPI). Заявки, чат, план и гранты пишутся в PostgreSQL через SQLAlchemy. Клиент создаёт заявку с описанием проблемы. Оператор утверждает её, и только тогда сервис передаёт uuid клиента и id заявки на порт приёма ретранслятора.

Ретранслятор может стоять на другой машине. Адрес приёма задаётся `RELAY_INGEST_URL`, общий секрет — `RELAY_INGEST_TOKEN`. Своего Redis у заявок нет.

Заявку создаёт клиент с базовой аутентификацией, логин `client`. Очередь и правки оператора требуют логин `operator`. Вызовы клиента по уже созданной заявке несут `X-Ticket-Token`: хеш токена лежит в строке заявки. Роль в чате и в подтверждении берётся из учётной записи.

Номер секции считает приложение: `crc32(account_id) % 4`. Каталог `shard_directory` помечает все четыре секции как `local`.

## Что отвечает сейчас

| Метод | Кто | Зачем |
| --- | --- | --- |
| `POST /api/v1/tickets` | клиент | Заявка в статусе `queued`, `ticket_token` |
| `GET /api/v1/tickets` | оператор | Очередь из PostgreSQL, без uuid клиента и без секретов сессии |
| `GET /api/v1/tickets/{id}` | оператор или клиент с токеном | Описание и статус. Uuid клиента виден клиенту и назначенному оператору |
| `POST /api/v1/tickets/{id}/claim` | оператор | Утверждение: туннель в ретрансляторе, статус `assigned`, секрет оператора |
| `POST /api/v1/tickets/{id}/release` | назначенный оператор | Вернуть заявку в очередь, если окно закрыто при открытой заявке |
| `GET /api/v1/tickets/{id}/session` | оператор или клиент с токеном | Чат, шаги, грант, `tunnel_id` и секрет своей роли. Чужому оператору — только статус |
| `POST /api/v1/tickets/{id}/messages` | участник сессии | Чат |
| `POST /api/v1/tickets/{id}/control-requests` | оператор, заявка его | Запрос управления |
| `POST .../control-requests/{grant}/decision` | клиент и токен заявки | `remote_control` или `guided` |
| `POST /api/v1/tickets/{id}/input` | оператор, заявка его | Событие ввода |
| `POST .../input/{action}/result` | клиент и токен заявки | `applied` или `rejected_by_client` |
| `POST /api/v1/tickets/{id}/actions` | оператор, заявка его | Отказ правил |
| `POST /api/v1/tickets/{id}/plans` | оператор, заявка его | План шагов |
| `POST .../steps/{step}/observations` | клиент и токен заявки | Наблюдение |
| `POST .../steps/{step}/complete` | оператор, заявка его | Шаг `done` |
| `POST .../steps/{step}/revise` | оператор, заявка его | Старый шаг `cancelled` |
| `POST /api/v1/tickets/{id}/problems` | оператор, заявка его | Дочерняя проблема |
| `POST /api/v1/tickets/{id}/resolution` | участник сессии | «Решено» клиента ставит `resolved` сразу. «Не решено» с комментарием ставит `closed`. Предложение оператора ставит `awaiting_client`, если шаги закрыты |

Тело запроса ограничено 1 МБ, план — 20 шагами. Активный грант управления — 30 минут. Туннель в Redis ретранслятора живёт 15 минут.

## Swagger

Страница при живом сертификате: `https://127.0.0.1/swagger/tickets/index.html`. Процесс слушает `18080` и на хосте опубликован только как `127.0.0.1:18080`. Если сертификата нет, страница открывается на `http://127.0.0.1:8080/swagger/tickets/index.html`.

Отдельный запуск: `docker compose -f ticket-service/docker-compose.yaml up -d --build`. Адрес ретранслятора — переменная `RELAY_INGEST_URL`.

Кто какой вызов принимает, записано в [SECURITY.md](SECURITY.md). Риски и планы — в [RISKS.md](RISKS.md) и [PLANS.md](PLANS.md).
