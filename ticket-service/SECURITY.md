# Безопасность сервиса заявок

Контракт вызовов в [отчёте](../README.md#api).

Сервис принимает две базовые учётки: `client` и `operator`. Пароли сравниваются по хешу через `hmac.compare_digest`. После создания заявки клиент доказывает владение заголовком `X-Ticket-Token`. В базе лежит только хеш токена.

Оператор видит очередь без uuid клиента и без секретов сессии. Полную сессию и секрет оператора получает только назначенный оператор. Клиент с токеном заявки получает секрет клиента. Один ответ не содержит оба секрета.

Захват заявки открывает туннель в ретрансляторе и сохраняет секреты в журнале этой заявки. Возврат в очередь, `resolved` и `closed` просят ретранслятор удалить туннель. Чужой оператор получает только статус, флаг `owned: false` и причину переключения, без чата, шагов и ввода.

Текст сообщений, шагов, наблюдений и ввода режется правилами. Управляющие символы не проходят. Код клавиши — латиница, цифры и `_`, не длиннее 32 символов. Координаты указателя — целые от 0 до 10000. Наблюдение по шагу не длиннее 4000 символов, комментарий результата ввода — 500. Тело HTTP ограничено 1 МБ.

Сервис не принимает оболочку, удаление файлов, выгрузку секретов и открытие входящего порта. Эти намерения пишутся как отказ и на клиента не уходят.
