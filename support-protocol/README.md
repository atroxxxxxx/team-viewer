# Общий контракт

Пакет входит в окна из [отчёта](../README.md#c4). Пакет `support_protocol` используют клиент и оператор. Здесь проверка намерения, текста шага и события ввода, HTTP-клиент сервиса заявок и аргументы ffmpeg для одного RTSP-пути.

`load_endpoints` читает `config.yaml`: схема и адрес заявок, хост и сессионный порт ретранслятора, логин, пароль и `tls_verify`. `TicketAPI` шлёт Basic и, после создания заявки, заголовок `X-Ticket-Token`. `LocalRTSPBridge` принимает ffmpeg на `127.0.0.1` и отдаёт поток в сессионный порт после строки `CLIENT <uuid> <секрет>` или `OPERATOR <uuid> <секрет>`. Секрет короче или длиннее 64 символов мост не отправляет. Источник захвата экрана для ffmpeg — локальный дисплей вида `:0`.

Правила совпадают с кодом в `policy.py` и с описанием в `safety-policy`. Запрещённые намерения включают удаление, оболочку (`run_shell`), стойкий доступ и выгрузку секретов. Scope сравнивается по точному слову: `pointer`, `key` или `text`. Текст события не длиннее 200 символов, шаг плана — 500. Проверка оператора не заменяет проверку клиента.


## Настройки и ошибки desktop-приложений

`UserSettings` хранит отдельные `client.json` и `operator.json`. Каталог: Linux `$XDG_CONFIG_HOME/remote-support` (обычно `~/.config/remote-support`), Windows `%APPDATA%/RemoteSupport`, macOS `~/Library/Application Support/RemoteSupport`. Для изоляции тестов и отдельных профилей можно задать `SUPPORT_SETTINGS_DIR`.

Сохраняются адреса, проверка TLS, переключатели, активная вкладка, геометрия окна, разделитель оператора и параметры видео клиента. Настройки подключения и переключатели записываются сразу; геометрия сохраняется через 200 мс после изменения и при закрытии. Запись атомарная, файл создаётся с правами только для владельца на Unix. Отсутствующий или повреждённый файл не мешает запуску; допустимые поля старого плоского формата читаются, неизвестные поля отбрасываются. Пароли и токены в это хранилище не записываются. Они остаются в существующем базовом конфиге и памяти сессии.

HTTP использует connect timeout 1,5 с, read timeout 3 с для опроса и 15 с для POST, write/pool timeout 3 с. POST сохраняет прежний бюджет ожидания, поскольку принятие и закрытие заявки обращаются к relay с таймаутом 5 с. Детали ошибок и исходные исключения попадают в журнал, интерфейс получает отдельный безопасный текст. Повторы одной ошибки журналируются не чаще раза в 30 с до восстановления связи. Логи desktop находятся в `logs/` внутри каталога настроек и ротируются. У оператора очередь опрашивается раз в 3 с без наложения одинаковых запросов. Клиент без активной заявки проверяет `/health` раз в 3 с. Изменение доступности сервиса не перезаписывает настройки.

## Видео

Размер кадра остаётся 640×360, чтобы сохранить совместимость координат управления и rawvideo-декодера. По умолчанию 60 FPS, CRF 23, максимум VBV 2 Мбит/с, GOP 1 с, без B-кадров. В настройках клиента FPS задаётся положительным целым числом без верхнего ограничения приложения; CRF доступен в пределах 18–35. Применение параметров видео разрешено без активной заявки, новые значения используются при следующей публикации. Ограничение VBV не включает накладные расходы RTSP/TCP.

Плеер ограничивает анализ потока до 32768 байт / 100000 мкс, включает `nobuffer` и `low_delay`, убирает повторный `scale`. Команды ввода клиента исполняются последовательно; завершение сеанса отменяет очередь и останавливает текущий процесс ввода. GUI дренирует stdout, сохраняет незавершённый RGB-кадр и оставляет только последний полный кадр. Показ планируется при получении полного кадра одним отложенным вызовом Qt, без периодического ограничения частоты. У rawvideo-кодировщика плеера явно задан один выходной поток, чтобы не накапливать кадры во frame-thread очереди. Счётчик FPS рядом с экраном учитывает только новые реально нарисованные кадры, а не повторные repaint окна. Закрытие отменяет очередные фоновые действия, отключает обработчики результатов и останавливает таймеры/процессы; уже начатый HTTP-запрос заканчивается в рамках своих таймаутов.

Целевые тесты (для GUI требуется PyQt5):

```bash
QT_QPA_PLATFORM=offscreen python -m pytest -q support-protocol/tests operator-app/tests scripts/tests
```


Модели оператора скачиваются и выполняются в отдельном управляемом Python-процессе. При закрытии окна процесс завершается; длительное скачивание или инференс не удерживает глобальный пул Qt. Отложенные действия оператора привязаны к исходной заявке и отменяются при её смене. Списки шагов и очередь обновляются по ID с сохранением выбора и прокрутки.


Профиль настроек версии 3 автоматически поднимает частоту старых профилей 1/2 ниже 60 FPS до 60 при первом запуске; адреса, TLS, качество и остальные параметры сохраняются. После миграции можно явно выбрать любую положительную целую частоту, включая 120/144/240 FPS или меньшую частоту для слабой машины и канала. Замеры полного локального пути до отрисовки Qt приведены в [проверке 30 FPS](../docs/video-30fps-check.md).
