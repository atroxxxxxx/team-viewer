# Приложение оператора

Настольное приложение на Python и PyQt5. В нём работает оператор техподдержки. Та же роль и тот же протокол доступны языковой модели: модель не ходит в обход приложения и не открывает сессионный порт сама.

## Обязанности

- Очередь заявок и захват одной заявки. Повторный захват занятой заявки получает отказ.
- Чтение описания проблемы и чат.
- Исходящее подключение к сессионному порту ретранслятора строкой `OPERATOR`, uuid клиента и секретом оператора из ответа захвата. Просмотр идёт через локальный RTSP-мост. Секрет клиента этому окну не выдаётся.
- Запрос разрешения на управление. Без активного `control_grant` команды ввода не отправляются.
- Перед отправкой каждого действия — проверка правилами из [safety-policy](../safety-policy/OPERATOR_RULES.md) и валидатором оператора.
- Если разрешения нет: составить план шагов, принять наблюдения, отметить шаг, завести дочернюю проблему и план, если шаг сам создал неисправность.
- Предложить закрытие, если шаги закрыты. Клиент может закрыть заявку сам кнопками «Решено» и «Не решено». Закрытие окна при открытой заявке вызывает `POST /release` и возвращает её в очередь с пометкой о штатном завершении. Молчание панели 60 секунд возвращает заявку с пометкой о потере связи.
- Писать в журнал каждое решение, включая действия, которые правила запретили. Журнал хранит сервис заявок.

Сборка пакета для Debian описана в [DEBIANIZE.md](../DEBIANIZE.md).

## Запуск

Адреса и учётка лежат в `config.yaml`. `ticket` — схема, адрес и порт сервиса заявок. `relay` — хост и сессионный порт. `auth` — логин `operator` и пароль. Пока nginx отдаёт локальный HTTPS, заявки идут на `https://127.0.0.1:443` с `tls_verify: false`. Если сертификата нет, ставятся `scheme: http` и `port: 8080`. Идентификатор оператора считается из логина.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt -r requirements-models.txt
.venv/bin/python -m operator_app.main
```

Только человек, без скачивания моделей: `.venv/bin/python -m operator_app.main --no-models`. В этом режиме хватает `requirements.txt`.

Очередь, захват и просмотр экрана идут в сервисы. Чат, план, разрешение и закрытие — туда же. Клик по кадру и поле текста становятся событием ввода только при активном гранте и после валидатора.

## Оператор-человек и связка моделей

Без флага первый запуск смотрит память машины и скачивает три локальные модели с Hugging Face, если файлов ещё нет. Кнопка «Шаг модели» гоняет их по очереди: текстовая читает заявку, зрительная описывает кадр, модель решения возвращает одно действие. Действие — совет в чат, план, запрос управления, движение мыши, клавиша или текст. Код режет ответ до отправки. Ввод от модели по умолчанию выключен отдельной галкой.

```bash
python3 -m operator_app.main --no-models
```

`--no-models` ничего не скачивает и оставляет только человека: кнопка шага модели выключена.

| Память | Текст и решение | Кадр |
| --- | --- | --- |
| меньше 8 ГиБ | Qwen2.5 0.5B, Q4 | SmolVLM 256M |
| от 8 ГиБ или 4 ГиБ VRAM | Qwen2.5 1.5B, Q5 | SmolVLM 500M |
| от 16 ГиБ или 8 ГиБ VRAM | Qwen2.5 3B, Q5 | Qwen2.5-VL 3B |
| от 32 ГиБ или 16 ГиБ VRAM | Qwen2.5 7B, Q5 | Qwen2.5-VL 7B |

Веса лежат в `operator-app/models` или в каталоге из `SUPPORT_MODELS_DIR`. Для скачивания и запуска нужны пакеты из `requirements-models.txt`. Оболочка правилами запрещена. Намерение `run_shell` режется так же, как удаление и выгрузка секретов.

Модель обязана подчиняться [правилам](../safety-policy/OPERATOR_RULES.md). Приложение отбрасывает ответ, если он не проходит валидатор, и пишет отказ в журнал. Дообучение на журнале этой сессии в продукт не входит — см. [training-log](../training-log/README.md).

Отчёт по курсовику — в корневом [README.md](../README.md). Истории этого окна: [заявка и экран](../docs/uml/story-session.png), [управление и шаги](../docs/uml/story-steps.png), [закрытие](../docs/uml/story-close.png). Какие документы обязательны у части, сказано в [PARTS.md](../docs/PARTS.md).

Настройки из окна сохраняются сразу после применения и восстанавливаются при запуске. Базовые адреса и учётные данные читаются из `config.yaml`; пользовательские настройки их дополняют. Файл пользовательских настроек не содержит паролей и токенов. Расположение и проверки описаны в [support-protocol](../support-protocol/README.md). Сеанс начинается через очередь заявок, а не по ID и паролю. Очередь не содержит uuid клиента. Завершить заявку может клиент. Оператор может предложить закрытие или вернуть заявку в очередь, закрыв окно. Документы безопасности этой части лежат в [client-app/SECURITY.md](../client-app/SECURITY.md), [RISKS.md](../client-app/RISKS.md) и [PLANS.md](../client-app/PLANS.md).
