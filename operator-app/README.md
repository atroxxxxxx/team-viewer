# Приложение оператора

Настольное приложение на Python и Qt 5/6. В нём работает оператор техподдержки. Та же роль и тот же протокол доступны языковой модели: модель не ходит в обход приложения и не получает сырой RTSP мимо токена заявки.

## Обязанности

- Очередь заявок и захват одной заявки. Повторный захват занятой заявки получает отказ.
- Чтение описания проблемы и чат.
- Исходящее чтение экрана и, если она есть в заявке, камеры с ретранслятора.
- Запрос разрешения на управление. Без активного `control_grant` команды ввода не отправляются.
- Перед отправкой каждого действия — проверка правилами из [safety-policy](../safety-policy/OPERATOR_RULES.md) и валидатором оператора.
- Если разрешения нет: составить план шагов, принять наблюдения, отметить шаг, завести дочернюю проблему и план, если шаг сам создал неисправность.
- Предложить закрытие. После согласия клиента сервис заявок отмечает выход из чата и удаляет медиатокены в Redis. Ретранслятор отдельно не вызывается: следующая RTSP-команда без токена получает 401, клиент останавливает публикацию.
- Писать в журнал каждое решение, включая действия, которые правила запретили. Журнал хранит сервис заявок.

## Запуск прототипа

Адреса и учётка лежат в `config.yaml`: `ticket` — схема, адрес и порт сервиса заявок, `relay` — RTSP ретранслятора, `auth` — логин `operator` и пароль. Пока nginx отдаёт локальный HTTPS, это `https://127.0.0.1:443` и `tls_verify: false`. Если сертификата нет, ставятся `scheme: http` и `port: 8080`. Поле `operator_id` в теле захвата сервис не читает: идентификатор считается из логина.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m operator_app.main
```

Очередь, захват и просмотр экрана идут в сервисы. Чат, план, разрешение и закрытие — туда же. Клик по кадру и поле текста становятся событием ввода только при активном гранте и после валидатора.

## Оператор-модель

Модель сидит внутри приложения. Отдельного канала мимо правил у неё нет. Кнопка «Шаг модели» делает один проход: кадр описывает зрительная модель, следующее действие выбирает текстовая, код режет ответ до отправки. Ввод от модели по умолчанию выключен отдельной галкой.

Связка для локального Ollama, без облака:

| Роль | Модель | Зачем |
| --- | --- | --- |
| Правила | код в `support-protocol` | Запреты не отдаются модели на решение |
| План, чат, закрытие | `qwen2.5:7b` | Русский, короткий JSON, один следующий шаг |
| Кадр экрана | `qwen2.5vl:7b` | Окна и текст ошибки. Пароли модель просят не переписывать |

На машине около 8 ГБ памяти те же роли закрывают `qwen2.5:3b` и `qwen2.5vl:3b`. Если русский не нужен, планировщик можно сменить на `llama3.1:8b`. Имена в форме меняются: это теги Ollama, не зашитая поставка.

```bash
ollama pull qwen2.5:7b
ollama pull qwen2.5vl:7b
```

Адрес по умолчанию `http://127.0.0.1:11434`. Приложение принимает только `http` или `https` на `127.0.0.1`, `localhost` или `::1`. Агентный каркас с оболочкой и произвольными инструментами здесь не нужен: цикл уже в приложении, а оболочка правилами запрещена. Намерение `run_shell` режется так же, как удаление и выгрузка секретов.

Модель обязана подчиняться [правилам](../safety-policy/OPERATOR_RULES.md). Приложение отбрасывает ответ, если он не проходит валидатор, и пишет отказ в журнал. Дообучение на журнале этой сессии в продукт не входит — см. [training-log](../training-log/README.md).
