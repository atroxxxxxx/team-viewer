# Ретранслятор

Сервис на Go со своим Redis и без базы. Заявка в работе живёт 5–15 минут, поэтому в Redis хранятся uuid клиента и внутренний `tunnel_id` с TTL 15 минут. Туда же пишется id заявки, чтобы снять туннель при закрытии.

Сервис заявок может быть на другом сервере. Наружу открыты два порта:

| Порт | Кто | Зачем |
| --- | --- | --- |
| `18082` | сервис заявок | `POST /api/v1/tunnels` после утверждения, `DELETE /api/v1/tunnels/{ticket}` при закрытии. Заголовок `Authorization: Bearer` |
| `8554` | клиент и оператор | Первая строка `CLIENT <uuid>` или `OPERATOR <uuid>`. Дальше по соединению идёт RTSP |

RTSP слушает только `127.0.0.1:18554` внутри процесса. Сессионный порт проверяет uuid в Redis и склеивает внешнее соединение с этим локальным RTSP. Поток не публикуется отдельным портом в интернет. Приложения на своих машинах тоже принимают ffmpeg на localhost и прокидывают байты в порт `8554`.

`GET /health` на порту `18082` проверяет Redis.

Отдельный запуск: `docker compose -f relay-service/docker-compose.yaml up -d --build`.
